# 심화 타로 상담 개선 계획

작성일: 2026-11-10. 범위: 복냥 심화 타로의 질문 판단, 근거 기반 풀이, 확인 카드, 토스 화면, 평가·추적. 구현과 최소 검증을 마쳤으며 로컬 5190에 적용했다. 운영 배포·실제 환경변수·DB 마이그레이션은 변경하지 않았다. 결과는 [구현 보고서](tarot-implementation-report.md)에 기록했다.

## 실행 범위 변경 (사용자 지시 반영)

사례 검증을 최소화하라는 지시에 따라 원안의 48개 데이터셋·72/216개 평가·36개 통합 비교·20쌍 사람 검토는 실행하지 않는다. 대표 3개(현재 마음 탐색, 관계 회복, 두 대안 비교)에서 구성별 1회만 비교한다. 오류 수정에 필요한 같은 사례 재확인과 브라우저 1건만 추가하며, 통계적 우위나 운영 전환을 확정하지 않는다. 원래 제안한 점수·p95·표본 수 목표는 운영 검증의 참고 목표이며 이번 최소 검증의 달성 결과가 아니다.

## 결정 요약

**사용자에게 전달되는 최종 문장은 기존 `gemini-3.1-flash-lite`로 고정한다.** 본 풀이·카드별 설명·종합 결론·행동 조언·확인 카드뿐 아니라 사용자에게 보여주는 추가 질문·선택지·상담 요약도 Gemini가 작성한다. GPT 원문은 사용자 화면이나 공개 API 응답에 노출하지 않는다.

GPT는 내부 질문 판단과 근거 분석, Jev는 평가와 오류 분류에 활용한다. 첫 후보는 `gpt-6-luna` 내부 질문 판단 + Gemini 사용자 문장 작성이다. `gpt-6.1-terra` 내부 분석은 본 풀이에서만 로컬에 적용했다. 확인 카드의 추가 GPT 분석은 최소 비교에서 이득이 없어 제외하고 Gemini 단독을 유지했다. Gemini 단독 기준선과 동일 조건에서 비교하며, 후보가 더 좋다는 결론은 아직 없다.

Jev는 먼저 오프라인 평가에만 사용한다. 사용자 응답마다 Jev 검사와 재생성을 추가하지 않는다. 오프라인 평가가 사람의 판단과 맞는지 확인한 뒤에만 비동기 표본 평가를 도입한다.

## 현재 상태와 유지할 것

- `catbot-backend/services/tarot_service.py`: `Decision`은 `TAROT_PLANNING_MODEL`, 풀이·확인 카드는 `TAROT_READING_MODEL`을 사용하며 기본값은 모두 `gemini-3.1-flash-lite`다.
- 질문 판단은 원문과 모든 추가 답변을 반영하고, 추가 질문은 한 번에 하나씩 최대 2회다. 배열은 현재 2/3장, 시간 흐름 2종, 대안 비교 2/3개다.
- 서버가 카드를 추첨·저장한다. 메이저 22장과 전체 78장 덱, 정방향 및 카드별 문서 근거 검증이 이미 있다. 추첨·자리 배정·사용량·소유권을 모델에 맡기지 않는다.
- `tarot_knowledge.py`는 지정된 카드의 자료만 조회하고 근거 ID의 소속을 검증한다. **ID가 유효하다는 사실만으로 문장의 의미까지 근거와 일치한다고 보장하지는 않는다.** 의미 검증이 평가의 주요 대상이다.
- 재시도 시 같은 카드와 자료 버전을 유지하고, 무료 상담/구매 차감·동시 요청·완료 결과 복구를 보호하는 기존 코드를 유지한다.
- 기존 사주 모델 비교에 Jev `jev-1.14.0` 호출·블라인드 채점·비용 집계 코드가 있다. 인증과 API 형식을 재사용하되, 사주 평가 항목과 점수는 타로에 전용하지 않는다.
- 현재 5190의 실제 AI 로컬 실행기는 `/tarot/sessions`를 차단한다. 타로 실제 브라우저 검증에는 별도의 로컬 인증 연결이 먼저 필요하다.

## 해결할 품질 문제

1. 사용자 사실을 지어내거나 카드의 상징을 현실의 사실로 바꾸지 않으면서, 질문에 직접 답하는 상담을 만든다.
2. 카드별 풀이·종합 답변·최종 권고의 방향과 시간 범위를 일치시킨다. 단순한 자신감이나 긍정적인 말투를 품질로 보상하지 않는다.
3. 이미 받은 정보를 재질문하지 않는다. 현재 반복 검사는 문장 동일성 중심이므로 표현을 바꾼 동일 질문도 평가에 넣는다.
4. 확인 카드는 원래 해석에서 무엇이 더 분명해졌는지 설명하고, 같은 조언만 늘어놓지 않는다.
5. 문장 수를 채우느라 길어지는 출력을 줄인다. 명확한 권고와 미래·타인 마음에 관한 단정을 구분한다.

## 모델 비교 설계

| 구성 | 내부 질문 판단·분석 | 모든 사용자 문장 |
|---|---|---|
| A: 현재 기준선 | Gemini 3.1 Flash Lite | Gemini 3.1 Flash Lite |
| B: 판단 분리 후보 | GPT-6 Luna로 질문 판단 | Gemini 3.1 Flash Lite |
| C: 로컬 적용 구성 | Luna로 질문 판단 + Terra로 본 풀이 근거 분석. 확인 카드는 추가 GPT 분석 없음 | Gemini 3.1 Flash Lite |

- 기존 모델 팩토리와 구조화 응답을 사용한다. 모델별 추론 설정·응답 스키마·시간 제한 호환성을 확인한다. 새 에이전트나 LangGraph 전환은 필요하지 않다.
- 현재 `Decision`에는 사용자용 질문·요약 문자열도 섞여 있다. 단순히 `TAROT_PLANNING_MODEL`을 GPT로 바꾸지 말고, 내부 판단(배열·정보 부족 유형·확인할 항목·원문 근거)과 Gemini 문장 작성을 분리한다. Gemini가 쓰는 질문도 내부 판단 및 기존 최대 2회 질문 규칙과 일치하는지 검사한다.
- B와 C의 사용자 문장 작성기는 같은 Gemini 모델·설정·프롬프트 버전을 사용한다. C에서 추가하는 것은 구조화된 내부 분석이며, 순수한 모델 교체 실험이 아니라 단계 추가 실험임을 보고서에 명시한다. 이후 프롬프트 개선은 따로 측정한다.
- 내부 분석은 카드·자리·근거 ID, 해석 후보·충돌·미확인 사항을 구조화한다. Gemini에 사용자 원문과 원래 카드 근거도 함께 제공하며, GPT 분석을 검증된 사실이나 사용자 지시로 취급하지 않는다.
- 질문 판단은 원문·답변에 대한 허용 배열과 정보 부족 여부로 평가한다. 풀이 비교에서는 동일한 기준 배열·카드·자리·근거 스냅샷과 Gemini 작성기를 고정한다. 구성별로 다른 카드를 뽑아 점수를 비교하지 않는다.
- 질문·본 풀이·확인 카드에서 GPT 원문이 사용자 응답으로 직접 전달되는 경로가 없는지 검사한다. Gemini 실패 시 GPT 답변으로 대체하지 않고 기존 재시도·오류 안내 경로를 사용한다. `TAROT_READING_MODEL`은 GPT 후보 비교 대상에서 제외한다.
- 단계별 비교와 별도로, 최종 후보와 기준선을 실제 상담 흐름 전체에서 비교한다. 여기서는 모델이 결정한 배열과 최대 2회의 추가 질문도 포함한다.

## Jev 활용

### 입력과 판정

`state`에는 익명화한 고민·추가 답변, 확정 배열·카드·자리, 실제 제공한 근거 구절, 평가할 답변을 담는다. 내부 GPT 분석과 최종 Gemini 답변은 단계별로 따로 평가한다. 내부 분석에는 문체 점수를 적용하지 않으며, 아래 종합 가중치는 사용자용 Gemini 답변에만 적용한다. 구성 이름·기존/신규 구분은 숨긴다. `questions`에는 서로 독립적인 평가 항목을 넣고 버전과 입력 해시를 저장한다.

- **Score**: 근거 충실성 30%, 질문·조건 반영 20%, 카드·종합·결론의 일관성 20%, 행동의 구체성 15%, 한국어 명료성·중복 억제 15%. 각 항목은 0~4점의 구체적인 기준을 정의하고 `합계(weight × score/4 × 100)`으로 환산한다.
- **Noul**: 미확인 개인 사실의 단정, 자리의 시간 범위 혼동, 같은 정보 재질문, 근거와 반대인 해석, 확인 카드의 실질적 새 정보 여부를 각각 판정한다. 확률을 즉시 차단 기준으로 쓰지 않고 사람 라벨로 임계값을 보정한다.
- **Choice**: 필요할 때 질문 목적·정보 부족 유형을 독립적으로 분류해 GPT 판단과의 불일치를 찾는다. 카드 선택이나 사용자 최종 의사결정에는 쓰지 않는다.

Jev는 설명문 생성기가 아니다. 사람이 읽을 상세 비평을 생성한다고 가정하지 않는다. 수정에는 항목별 점수·위반 플래그와 원래 근거 자료를 제공한다. Jev의 confidence를 정답 확률이나 미래 예측 정확도로 해석하지 않는다. 타로가 실제 미래를 맞히는지는 이 평가의 대상이 아니다.

### 사람 검토와 오프라인 운영

- 개발용 결과 20쌍을 모델명을 가리고 검토해 Jev의 선호와 차이를 비교한다. 특히 길고 확신에 찬 문장에 대한 편향을 확인한다.
- 사람 선호와 Jev 선호의 일치율 80%를 초기 보정 목표로 둔다. 미달이면 평가 기준을 수정하고, Jev 점수를 내부 처리 구성 전환의 단독 근거로 사용하지 않는다. 최종 작성기는 평가 결과와 무관하게 Gemini로 유지한다.
- 거부·시간 초과·빈 결과·스키마 오류를 모두 실패율과 비용에 포함한다. 채점 API 실패는 0점으로 처리하지 않고 미채점으로 남긴다.
- 평가자의 지시를 바꾸려는 사용자 입력·모델 출력은 데이터로 격리한다. 개인정보가 있는 운영 상담을 외부 채점 서비스에 자동 전송하지 않는다. 초기 평가는 합성 데이터만 사용한다.
- 사람과 일치가 확인된 이후 별도 옵션으로 신규 상담의 5%를 비동기 평가할 수 있다. 이 단계는 운영 데이터 처리 범위와 비용을 검토한 뒤 적용하며, 평가 장애가 상담 응답을 막지 않게 한다.

## 최소 사례와 실제 실행량

- 대표 합성 사례는 3개다. 현재 상태 2장, 과거-현재-미래 3장과 과거 자리 확인 카드, 두 대안 비교와 마이너 카드 근거를 포함한다.
- 수정 후 비교는 3개 사례 × Gemini 단독/Luna 판단/Terra 본 풀이 분석 3구성 × 1회 = **9개 평가 레코드**다. 추가 반복·대규모 홀드아웃 평가는 하지 않았다.
- 수정 전 6개 실행에서 관계 회복 2개가 다른 카드의 근거 ID 인용으로 실패했다. 실패·비용을 숨기지 않고 별도 보존했다. 같은 사례의 교정 확인, 확인 카드의 대상 범위에 맞춘 평가 보완 및 실제 브라우저 1건을 진행했다. 새 사례는 추가하지 않았다.
- 모든 평가 저장소는 합성 메모리 저장소다. 실제 AI/Jev 호출만 수행하고 운영 상담·무료분·구매 원장은 변경하지 않는다. 로컬 타로는 별도 임시 SQLite를 사용한다.
- 본 풀이 자동점수는 Gemini 85.16, Luna 판단 84.62, Terra 분석+Gemini 88.14였다. 3건·단일 실행이므로 성능 우위를 확정하지 않는다. 원안의 기준선 대비 5점 개선 목표에는 미달하며 사람 블라인드 보정도 실시하지 않아 운영 자동 전환은 보류한다.
- 평가 도구의 기본 예산은 US$3이다. 토큰 실측 기반 추정치와 상담당 US$0.50의 여유를 확인하며, 이는 공급자 청구 상한 자체를 설정하는 기능은 아니다.

## 응답·화면 개선

- Gemini가 작성한 답변에서 질문에 대한 핵심 답과 근거부터 보여준다. 카드별 상세, 카드 관계, 현실 확인 사항, 다음 행동 순서로 읽을 수 있게 한다. GPT 내부 분석은 사용자에게 직접 전달하지 않는다.
- 카드별 분량은 참고 목표로 3~5문장, 종합은 2~4문장부터 실험한다. 상황에 필요한 근거를 생략하지 않으며 문장 수 자체를 품질 점수로 삼지 않는다.
- 미래를 확정하는 표현이나 타인의 마음을 알아냈다는 표현 대신, 확인할 조건에 근거한 진행·보류·관점 전환을 제시한다. 마음을 이해하려는 고민에 결정을 강요하지 않는다.
- 추가 질문은 받은 사실의 재확인보다 답에 따라 상담이 달라지는 정보 한 가지에 집중한다. 질문 한도·모름 응답·중복 방지는 서버에서 관리한다.
- 대기 안내를 질문 정리·카드 풀이 등 실제 단계와 맞춘다. 오류가 나면 동일 상담·카드로 재시도하고, 다시 뽑거나 구매를 중복 차감하지 않는다.
- 결과 표현 변경은 현재 API 구조로 먼저 해결한다. 카드 근거 ID와 내부 평가 점수는 일반 사용자 화면에 노출하지 않는다.

## 추적·로컬 검증

- LangSmith에서 하나의 상담 아래 GPT 내부 판단·선택적 분석, Gemini 사용자용 질문·풀이·확인 카드, Jev 평가를 구분한다. 상담/요청 ID, 모델·프롬프트·근거·덱·평가 버전, 단계별 시간·토큰·추정 비용, 재시도·캐시 여부를 연계한다. 최종 사용자 문장의 생성 모델이 Gemini인지 확인 가능하게 한다.
- 카드 근거와 모델 선택 버전은 생성 시점에 기록한다. 기존에 완료된 상담의 모델을 현재 환경 설정에서 역추정하거나 기존 답변을 재생성하지 않는다.
- Jev 평가에는 해당 생성 run ID를 붙여 추적한다. 텍스트·사용자 식별자 공개 범위는 기존 추적 정책에 맞추고 외부 평가용 입력은 익명화한다.
- 현재 사주용 로컬 프록시에 타로 경로만 열어서는 안 된다. 타로는 상담 접근 토큰과 계정 검증 계약이 다르므로 전용 테스트 계정·상담 권한을 연결하고 로컬에서만 사용한다.
- 테스트 저장소는 메모리/임시 SQLite를 우선 사용한다. 실제 AI를 사용해도 운영 무료분·구매 내역을 조작하지 않는다. 토스 SDK만 로컬 대체하며 실제 공급자·자료·검증 코드는 사용한다.

## 운영 검증의 참고 목표 (이번 최소 검증으로 달성 판정하지 않음)

- 고정 회귀 데이터에서 카드·자리·근거 ID·소유권·중복 차감·재시도 불변식 위반 및 GPT 내부 문장의 사용자 응답 직접 노출 **0건**. 모든 사용자 문장의 작성기는 기존 Gemini로 유지한다. 구조화 출력 최종 성공률 **99% 이상**. 작은 표본의 100% 통과를 운영 실패 확률 0으로 해석하지 않는다.
- Jev 종합 평균 **85/100 이상**, 현재 기준선 대비 **5점 이상 개선**, 사례 단위 95% 차이 구간이 0보다 클 것. 사람 블라인드 검토에서도 기준선 대비 선호율 **60% 이상**을 목표로 한다. 기준 미달·불확실이면 전환 보류 또는 검증 사례 추가다.
- 핵심 사실 조작·카드 뒤바뀜·근거와 반대인 핵심 결론은 종합점수와 무관하게 부적합 처리한다. Jev가 의심한 의미 오류는 사람 검토로 확정한다.
- 질문 판단 p95 **5초 이하**, 본 풀이 p95 **30초 이하**, 추가 질문에 사용자가 답하는 시간을 제외한 전체 생성 p95 **45초 이하**를 초기 목표로 둔다. 첫 파일럿에서 달성 가능성을 확인하고 목표 변경은 기록한다.
- 내부 GPT 판단·분석, Gemini 사용자 문장 작성, 검색·재시도·Jev 채점 비용을 구분해 집계한다. GPT를 썼다는 이유만으로 채택하지 않고 품질·지연·총비용을 함께 비교한다. 추가 분석의 효과가 없으면 해당 단계를 제외한다.

## 실행 순서와 배포

구현 완료 항목과 검증 결과는 [todo.md](todo.md) 및 [구현 보고서](tarot-implementation-report.md)에 기록했다. 순서는 기준선/데이터셋 → 평가 도구 → 모델 비교 → 프롬프트 개선 → 로컬 타로·화면·추적 → 통합 회귀와 점진 적용이다.

통과한 모델 구성은 기능 설정으로 신규 상담에만 적용한다. 테스트 환경 검증 후 운영 신규 상담의 5% → 25% → 100% 순으로 확대하는 안을 제안한다. 단계마다 최소 24시간·새 상담 100건 중 더 늦은 시점까지 관찰한다. 오류율이 기준선보다 1%p 이상 높아지거나 확정된 불변식 위반이 발생하면 신규 적용을 즉시 중단한다. 트래픽·기준선이 부족하면 기간을 연장한다. 진행 중/완료 상담의 카드·근거·출력은 유지한다. 운영 적용은 구현 결과 검토 후 별도 작업이다.
