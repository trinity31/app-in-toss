# 익명 인증 로컬 테스트

실제 고객 데이터, 토스 API, AI 모델, 결제를 호출하지 않는 MOCK 테스트입니다. 실제 앱인토스 브리지와 운영 mTLS 인증서 연결까지 검증하는 테스트는 아닙니다. 배포·업로드·운영 SQL 실행은 하지 않습니다.

## 실행

Node.js **24 이상**, 설치된 프런트엔드 node_modules, 백엔드 venv가 필요합니다. 두 저장소가 기존 위치 `Projects/app-in-toss/fortune-cat`, `Projects/catbot/catbot-backend`에 있어야 합니다.

```sh
cd /Users/trinity/Projects/app-in-toss/fortune-cat
npm run test:anonymous-session:local
```

브라우저에서 **http://127.0.0.1:5189** 를 여세요. 백엔드는 **127.0.0.1:8019** 에서만 실행됩니다. 두 포트가 이미 사용 중이면 이전 테스트를 먼저 종료하세요. 프런트엔드는 별도 임시 폴더에서 실행되어 `.env`·Firebase·Supabase·광고·Sentry를 로드하지 않습니다. 백엔드는 실제 키를 제거하고 외부 연결을 차단합니다. 종료는 실행 터미널에서 **Ctrl-C** 입니다.

## 먼저 확인할 것

1. 기본 **기존 익명 고객**에서 서비스 소개가 먼저 보이고 `시작하기` 후 로그인 동의 없이 기존 사주 1개·타로 1개와 남은 이용권이 보이는지 확인합니다.
2. **새로고침**하면 소개가 생략되고 새로운 익명 증명으로 보관함이 열려야 합니다. 저장되는 것은 소개 완료 표시뿐입니다. 토큰은 메모리에만 있습니다.
3. 상단 **테스트 조건 변경**에서 `연결된 기존 고객`을 적용합니다. 소유자가 `toss:202`이고 기존 기록·이용권이 유지되어야 합니다. `새 고객`은 기록과 유료 이용권이 없어 유료 생성 요청이 **402** 로 거절되어야 합니다.
4. `다른 사용자 풀이 요청`은 **404**, 같은 MOCK 주문의 지급을 반복하면 이용권이 추가로 늘지 않아야 합니다. MOCK 생성은 테스트 이용권을 차감하지만 실제 비용은 없습니다.
5. `이전 로그인 기록 미연결 고객`은 처음에 기록이 없습니다. `이전 토스 로그인 계정의 기록 연결` → `토스 로그인으로 기록 연결`을 선택할 때만 MOCK OAuth를 호출하고, 이후 `toss:303`의 기존 기록이 나타나야 합니다. 정상 익명 흐름은 이 기능을 자동 실행하지 않습니다.
6. 상단에서 `proof-failure`, `provider-unavailable`, `expired-session`, `unsupported`를 적용하면 보관함이 열리지 않아야 합니다. `native-timeout`은 **15초** 후 직접 다시 시도할 수 있게 됩니다. 오류 이후 자동 인증 재시도 루프는 없어야 합니다.

`처음 진입 화면 보기`는 현재 고객의 소개 완료 표시만 지웁니다. `모든 MOCK 데이터 초기화`는 이 테스트의 기록·주문·표시를 초기화합니다. 종료 후 임시 백엔드 DB는 삭제됩니다. 실제 고객 데이터에는 영향을 주지 않습니다.

## 자동 검증

```sh
node --test scripts/*.test.mjs
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs WEBKIT_EXECUTABLE=/path/to/pw_run.sh node scripts/tossAccountGate.browser.mjs
```

Chromium/WebKit 테스트는 같은 로컬 서버에서 새 진입·메모리 초기화 후 복원·기존/신규 고객·명시적 기록 연결·실패·소유권·주문 중복 방지·만료·로딩·작은 화면을 확인하고 스크린샷을 임시 폴더에 저장합니다. 앱 번들과 운영 AIT에는 이 MOCK 화면이나 테스트 서버가 포함되지 않습니다.
