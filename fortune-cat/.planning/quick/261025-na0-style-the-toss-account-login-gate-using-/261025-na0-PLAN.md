# Style the Toss account login gate

## Implementation contract

The gate explains why login is required and offers one clear login action before protected content. Reference the existing Intro and UserInfoInput screens: 20px mobile gutters, 22px headings, readable 15–16px text, existing semantic pink/neutral tokens, and a full-width bottom action with safe-area spacing. Use scoped component styling and existing TDS components where their installed API fits. Keep the anonymous-history warning visible and legible. Reject new dependencies, decorative hero artwork, gradients, global CSS changes, and any authentication behavior changes.

1. Style `src/components/TossAccountGate.jsx` and, if useful, a colocated scoped stylesheet. Retain the session subscription/expiry, explicit login handler, authenticated children, exact copy meaning, retryable error, and disabled busy button. Give the page an accessible primary heading, clear text hierarchy, visible focus, a touch target of at least 44px, and sufficient content space above the bottom action. Keep the error announced via `role="alert"`; expose loading without allowing duplicate login.

2. Verify with a local mocked browser at 320px and a representative phone viewport, plus 768px and desktop widths. Inspect idle, busy, failure/retry, and authenticated-child states; confirm no clipping, horizontal overflow, obscured warning, or action overlap at enlarged text. Use only mocked login/session/network behavior. Run the existing offline authentication tests and focused lint, then build the AIT artifact with supported Node24. Do not call production, model, or payment APIs.

3. Review the scoped diff and report local validation and the new AIT artifact. Preserve all unrelated WIP, especially `src/lib/tarotRuntime.js` and `scripts/tarotRuntime.test.mjs`. Print no credentials. Do not push, deploy, publish, change payment configuration, or alter backend authentication.
