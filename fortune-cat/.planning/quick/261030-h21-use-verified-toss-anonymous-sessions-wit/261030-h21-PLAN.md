# Verified anonymous Toss sessions without OAuth login

## Goal and hard boundaries

Customers can use readings, credits, purchases and both Tarot libraries without consenting to Toss OAuth login. All existing records, IDs, balances and consumed-free counters remain accessible to their verified owner. The anonymous identity is established through a native one-use authentication code, never a client-supplied anonKey. Existing OAuth clients and authenticated web/Android BFF flows remain compatible.

Implement and verify locally only. Do not push, deploy, upload an AIT, execute production SQL, write to production databases, change payment settings or make real Toss/provider/LLM/payment calls. The user will manually test locally before any deployment. ## Source-backed contract

- SDK 3.7 `User.createAnonymousKeyAuthCode()` returns `{code, expiresIn}`. Code lasts 300 seconds, is single-use and does not require OAuth login or personal-data consent. Reuse existing app-bound mTLS `exchange_anonymous_auth_code`; never call `appLogin`, `login-me`, raw anonKey `/verify`, or treat stored anonKey as authentication in new flows.
- Add strict `POST /toss-anonymous-session` accepting only `{code}` (bounded nonempty string, maximum 2048). Fresh provider exchange establishes the legacy anonKey. Response contains a short-lived own token, canonical `userId`, and `expiresIn`; no OAuth token or personal data. Return `Cache-Control: no-store`.
- Resolve verified anonKey through a new service-role-only SQL RPC. Existing `toss_legacy_account_links` mapping returns its `toss_uid`; no mapping returns the exact original legacy UID. Do not migrate records again, invent a new owner namespace, create quota rows or reset counters. Strictly validate RPC response and identifiers. Missing mapping schema/RPC/configuration/database/provider is 503; invalid/expired/reused proof is 401. No fallback when resolution fails.
- Own sessions use `X-Toss-Anon-Token`, distinct from existing `X-Toss-Access-Token`. Use standard-library HMAC-SHA256 with a dedicated backend-only `TOSS_ANON_SESSION_SECRET` of at least 32 characters, strict version/issuer/audience/subject/verified-anonKey/issued-at/expiry claims, and at most 900 seconds lifetime. Do not log the token or claims; tokens are authenticated, not encrypted. Reject malformed/noncanonical encoding, invalid signature, algorithm confusion, invalid types including booleans, future/expired/unbounded lifetimes and oversized tokens. No secret in browser, example files or repository; fixtures use unmistakably fake local values.
- Verify the token and re-resolve its embedded verified anonKey on every authenticated request. If canonical mapping changed after issuance, return 401 so the app obtains fresh native proof. Database unavailability remains 503. This preserves ownership and shared admission identity during concurrent old-client OAuth migrations. Never cache stale canonical mappings.
- Preserve previous origin/header rejection, resource ownership, server-selected model policy, payment quota checks, global order-once ledger and distributed rate/concurrency admission. Invalid credentials never fall through to weaker auth. Define handling of simultaneous auth headers explicitly and test it.
