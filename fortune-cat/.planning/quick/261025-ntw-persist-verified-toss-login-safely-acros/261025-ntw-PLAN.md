# Restore verified Toss login and simplify the login gate

## Implementation contract

Previously linked Toss users should enter protected screens automatically after a fresh verified login exchange. Keep access tokens and refresh tokens out of persistent browser/native storage. Native integration state is only permission to attempt login, never proof of authentication. Continue sending authorization codes to the existing server exchange, trusting only its validated personal account session, preserving the maximum 3600-second lifetime minus the 60-second safety margin and clearing sessions on HTTP 401. Backend authentication and billing behavior remain unchanged.

The installed SDK documents `TossAuth.isIntegrated()` as returning `boolean | undefined`; its legacy alias is `getIsTossLoginIntegratedService`. Query this bounded, noninteractive native integration check only when a protected gate needs a session. When it returns exactly `true`, attempt the existing bounded SDK login and server exchange. For `false`, `undefined`, unsupported bridges, exceptions, timeout, cancellation, or failed exchange, show an explicit retryable login screen. Do not trigger first-time consent automatically. Existing valid sessions must enter instantly without native checks or login calls.

1. Add failing offline tests, then implement a shared single-flight restore operation in `tossAccount.js` / `tossSession.js`. Concurrent consumers and React StrictMode remounts must share native check, login and exchange work. Publish successful session changes to subscribers. Prevent stale in-flight results from restoring an account after a clear/401, and prevent automatic retries or loops after a failed restore or unauthorized response. Permit manual login retry and a later successful session expiry refresh without retaining credentials between WebView lifetimes. Cover linked/unlinked/unknown users, bounded native failures, missing or malformed server identity, SDK/exchange failures, session expiry, concurrent restores, clear-during-restore, and unauthorized suppression. A fresh module instance must recover from native integration plus a new exchange without browser-stored bearer tokens.

Hold an accessible loading state while initial restoration is pending so returning users do not see a login form flash. Adopt subscription changes and timer expiry correctly, skip stale component updates after unmount, retain manual retry after cancellation/failure, and preserve safe-area spacing, bottom navigation, focus visibility, error announcements and disabled busy actions. Do not weaken protected-child rendering checks or automatically replay a failed paid operation.

3. Run all existing offline Node tests, focused lint, and mocked browser verification at 320px and a representative phone viewport. Exercise initial restoring, linked success, unlinked idle, unsupported/timeout fallback, failed restore/manual retry, instant valid session navigation, StrictMode/remount concurrency, expiry, HTTP401 without a restore loop, and unmount during a delayed exchange. Work only in the canonical `fortune-cat` project. Preserve existing UI commit `2610fa5`, unrelated `src/lib/tarotRuntime.js` and `scripts/tarotRuntime.test.mjs` edits, sibling apps and documents.
