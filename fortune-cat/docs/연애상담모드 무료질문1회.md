# 프런트 작업지시 — 궁합·애정운: "연애상담 모드 무료 질문 1회" 노출

> 작성: 2026-09-13 · 대상 repo: `app-in-toss/fortune-cat` · 백엔드 근거: `catbot-backend/docs/relationship/2026-09-12_claude_code_task_연애상담메뉴.md`
> 백엔드 상태: 구현·검증 완료, Supabase 마이그레이션 적용 완료. **프런트 수정 없이도 흐름은 동작**하지만, 사용자가 무료 1회가 있다는 사실을 화면에서 알 수 없어 기능이 묻힌다. 이번 작업은 **"알게 하는 것"**이 전부다.

## 🎯 목표

궁합·애정운 풀이를 다 본 사용자가 **"이 풀이는 연애상담 모드로 첫 질문 1회가 무료"**라는 걸 다음 세 시점에서 인지하게 한다.

1. 결제/무료공개 선택 화면 (미리보기 상태)
2. 전체 풀이를 다 읽고 후속질문 칩이 보이는 시점
3. 무료 질문을 사용한 직후 (다음 질문부터 결제라는 걸 미리 알림)

## 📌 백엔드 동작 (프런트가 전제로 삼을 것)

- 궁합·애정운 스레드의 **후속채팅은 무조건 연애상담 페르소나**로 답한다. 결제 여부·잔여 크레딧과 무관. 프런트가 모드를 선택하거나 보낼 필드는 **없다**.
- **무료 질문 1회 조건**: 궁합·애정운 스레드 + 구매 이력 없음(`total_purchased === 0`) + 후속 잔여 0 + 무료분 미사용(`free_followups_used === 0`). 계정당 1회. 조건 판단은 백엔드가 하고, 프런트는 **안내 표시 여부만** 같은 조건으로 계산한다.
- 첫 메시지: 백엔드가 그냥 답한다 (`paywall_required` 없음). 두 번째 메시지: 기존처럼 `paywall_required: "deep_reading"` → 기존 결제 카드. **결제 카드·결제 플로우는 변경하지 않는다.**
- 찐재물운·성격분석은 아무것도 바뀌지 않는다. 안내도 띄우지 않는다.

### API 변경점 (추가 필드만, 전부 기본값 있음)

| 엔드포인트 | 필드 | 의미 |
|---|---|---|
| `GET /quota` | `free_followups_used: number` | 무료 질문 사용 횟수 (0이면 미사용). `total_purchased`는 기존 필드 |
| `POST /deep-reading/chat` · `POST /deep-reading-match/chat` 응답 | `free_followup_used: boolean` | **이번 답변**이 무료 1회로 처리됐으면 true |

`lib/deepReadingPurchase.js`의 `getQuota()`는 그대로 쓰면 된다 (응답 JSON에 필드가 이미 포함됨).

## 🛠 구체 변경안 — `src/components/DeepReadingResult.jsx`

### 0. 대상 판정 헬퍼 (한 곳)

```js
// 궁합·애정운만 연애상담 모드 + 무료 질문 1회 대상
const LOVE_COUNSELING_TYPES = new Set(["new_year_2026_love", "new_year_compatibility"]);
const isLoveCounseling =
  LOVE_COUNSELING_TYPES.has(readingType) || (userData.isCompatibility ?? !!userData.partnerName);
```

- `readingType`은 이미 `userData.readingType`(L83)에서 온다. 궁합은 `isCompatibility`로도 잡는다 (보관함 재진입 시 `reading_type`이 `match:` 접두사라 값이 다르므로 둘 다 본다).
- **무료 질문 안내 가능 여부**: `isLoveCounseling && quota.total_purchased === 0 && (quota.free_followups_used ?? 0) === 0`. `applyQuota`(L221)에서 `freeFollowupAvailable` state 하나로 계산해 두고 아래 세 곳에서 쓴다.

### 1. 미리보기(결제/무료공개 선택) 화면 — 카피 수정 **(필수, 지금 문구가 틀림)**

- L1142~1144의 `" (무료 1회 공개는 전체 풀이만 열리고, 후속 질문은 포함되지 않아요)"` 는 궁합·애정운에서 **더 이상 사실이 아니다.**
  - `isLoveCounseling`이면 → `" (무료 1회 공개 + 연애상담 모드 첫 질문 1회 무료)"` 로 교체
  - 아니면 → 기존 문구 유지
- 무료 공개 버튼(L1170~) 라벨도 `isLoveCounseling`이면 "무료로 보기 + 연애상담 질문 1회" 정도로 차별화. 찐재물운·성격분석은 기존 라벨 그대로.

### 2. 전체 풀이를 본 뒤 (후속질문 칩 위) — 안내 배너 **(핵심)**

- 노출 조건: `!previewActive && freeFollowupAvailable`
- 위치: 마지막 assistant 메시지의 후속질문 칩 바로 위, 또는 하단 입력창 위 (현재 "남은 질문 N회" 라벨 자리, L1286 — 잔여 0이라 이 라벨은 안 보이므로 그 자리를 쓰면 레이아웃 재배치가 없다).
- 내용(초안, 문구 최종안은 Trinity 확정):
  - 제목: **연애상담 모드 · 첫 질문 1회 무료**
  - 본문: "사주 풀이가 아니라 두 분의 실제 상황을 듣고 답해요. 지금 궁금한 걸 하나 물어보세요."
- 칩을 탭하든 직접 입력하든 동작은 기존과 동일 (백엔드가 무료 처리). 프런트에서 카운트를 흉내 내지 말 것.
- `handleFreeReveal`(L360) 안의 주석 "무료 공개는 후속채팅을 지급하지 않는다 → 첫 질문에서 결제 유도"와 `setFollowupRemaining(0)`은 그대로 둬도 동작엔 문제없지만, 주석은 "궁합·애정운은 첫 질문 1회 무료(백엔드 판단)"로 고칠 것.

### 3. 무료 질문 사용 직후 — 사전 고지

- chat 응답 `result.free_followup_used === true`이면:
  - `freeFollowupAvailable`을 false로
  - assistant 메시지 아래(또는 입력창 위)에 한 줄: "무료 질문을 사용했어요. 이어서 질문하려면 결제가 필요해요 (10회)". 결제 버튼은 **여기서 새로 만들지 말고**, 다음 메시지 전송 시 뜨는 기존 결제 카드(L1221)에 맡긴다.
- 두 번째 메시지에서 `paywall_required`가 오면 기존 로직(L567~) 그대로. 결제 카드 문구도 그대로.

### 4. 보관함 재진입 (`LibraryPage` → `DeepReadingResult`)

- 재진입 시에도 `applyQuota`가 돌므로 조건이 맞으면 배너가 다시 뜬다. 이미 사용했다면 `free_followups_used === 1`이라 안 뜬다 (백엔드 카운터가 정본, 프런트 로컬 저장 불필요).

### 5. 홈 카드 카피 (선택)

- 궁합·애정운 카드 설명은 Supabase `new_year_fortune_types` / `ai_saju_types`의 `description_ko`가 그대로 렌더링됨 (`HomePage.jsx` L436·L497). 코드 수정 없이 데이터만 바꾼다. 문구 예: "연애상담 모드 첫 질문 무료". Trinity 확정 후 반영.

## 📊 이벤트 (Firebase `logEvent`, 기존 `firePaywall` 패턴)

- `free_followup_banner_shown` — 2번 배너 노출 시 (`reading_type`, `session_id`)
- `free_followup_used` — chat 응답 `free_followup_used === true` 수신 시 (`reading_type`, `thread_id`, `session_id`)
- 기존 `paywall_shown`(trigger: followup)은 두 번째 메시지에서 그대로 발화되므로 손대지 않는다. **관찰 지표는 `free_followup_used → paywall_shown → purchase_started` 전환.**
- 백엔드 `follow_up_question` 이벤트에는 `free_followup` 파라미터가 이미 들어가므로 서버 측 집계는 별도 작업 없음.

## 🚫 하지 말 것

1. 결제 카드·결제 플로우·가격 표시 로직 수정 금지. 안내 문구와 배너만 추가한다.
2. 찐재물운·성격분석 화면에 어떤 문구도 추가하지 말 것. `isLoveCounseling` 가드를 반드시 건다.
3. 프런트에서 무료 횟수를 로컬로 계산·저장하지 말 것. `/quota`와 chat 응답 플래그만 신뢰한다.
4. "연애상담 모드" 토글·선택 UI를 만들지 말 것. 모드는 백엔드가 풀이 종류로 자동 결정한다.
