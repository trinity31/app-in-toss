# 기능 구현 요청: 사용자 질문을 내부적으로 정리하는 AI 타로 3배열 해석

기존 타로 앱에 사용자의 자유로운 질문을 내부적으로 정리한 뒤, 뽑힌 카드 3장을 질문 맥락에 맞게 해석하는 기능을 구현해 주세요.

별도의 고민 정리 화면이나 버튼을 추가하지 마세요.  
사용자는 기존처럼 질문을 입력하고 카드 3장을 뽑은 뒤 최종 해석만 확인해야 합니다.

---

## 1. 기존 프로젝트 분석

기존 아키텍처와 코딩 스타일을 재사용하세요.  
관련 없는 코드는 리팩터링하지 말고, 가능한 한 작은 변경으로 구현하세요.
백엔드 수정이 필요한 경우 백엔드 개발 에이전트에 전달할 작업 지시서를 작성해 주세요.

---

## 2. 최종 사용자 경험

사용자 흐름은 다음과 같아야 합니다.

1. 사용자가 질문이나 고민을 자유롭게 입력한다.
2. 사용자가 카드 3장을 뽑거나 선택한다.
3. 앱이 백엔드에 사용자 질문과 카드 정보를 전달한다.
4. 백엔드가 사용자 질문의 핵심을 내부적으로 파악한다.
5. 백엔드가 카드 3장을 각각의 위치에 맞게 해석한다.
6. 사용자에게는 백엔드에서 전달하는 최종 타로 해석 결과만 보여준다.

### 흐름

`질문 입력 → 카드 3장 선택 또는 추첨 → 최종 해석`

---

## 3. 사용자 입력 처리

사용자는 완성된 문장이 아니어도 자유롭게 입력할 수 있어야 합니다.

입력 예:

- "그 사람과 다시 만날 수 있을까요?"
- "이직할까 말까 고민돼요."
- "올해 금전운"
- "지금 하는 사업을 계속해야 할까요?"
- "연락이 줄어든 상대의 마음이 궁금해요."
- "재회운"
- "새로운 인연"
- "앞으로 어떻게 해야 할지 모르겠어요."

짧거나 모호한 질문도 거절하지 마세요.  
AI가 입력 내용을 바탕으로 가장 자연스러운 핵심 고민을 내부적으로 구성해야 합니다.

빈 입력 처리와 최대 글자 수는 기존 앱 정책을 따르세요.  
기존 제한이 없다면 공백만 있는 입력은 제출할 수 없게 하고, 최대 1,000자로 제한하세요.

---

## 4. 사용할 타로 3배열 구조

이번 3배열은 질문에 맞게 과거·현재·미래 또는 다음 구조를 사용합니다.

### 1번 카드: 현재 상황

내부 역할:

- 현재 고민의 핵심 흐름
- 사용자가 처한 상황
- 지금 드러나고 있는 에너지
- 관계나 문제의 현재 상태

표시 제목:

`현재 상황`

position 값:

`situation`

### 2번 카드: 놓치고 있는 점

내부 역할:

- 사용자가 아직 보지 못하는 부분
- 숨은 영향이나 감정
- 반복되는 관계 패턴
- 문제를 어렵게 만드는 장애물
- 사용자의 추측과 다를 수 있는 가능성

표시 제목:

`놓치고 있는 점`

position 값:

`hidden`

### 3번 카드: 조언과 다음 행동

내부 역할:

- 지금 도움이 되는 태도
- 현실적으로 취할 수 있는 행동
- 선택할 때 참고할 기준
- 상황을 더 건강하게 바라보는 관점

표시 제목:

`조언과 다음 행동`

position 값:

`advice`

spreadType 값:

`situation_hidden_advice`

세 카드의 해석은 서로 역할이 겹치지 않아야 합니다.

## 5. 백엔드(AI)의 내부 처리

AI는 응답을 작성하기 전에 사용자에게 보이지 않는 내부 처리로 다음을 파악해야 합니다.

1. 사용자가 실제로 알고 싶어 하는 핵심 고민
2. 질문에서 확인할 수 있는 현재 상황
3. 사용자가 표현한 감정이나 바람
4. 사실이 아니라 사용자가 추측하고 있는 부분
5. 사용자가 이해하거나 결정해야 하는 문제
6. 세 카드가 각각 어떤 관점에서 답해야 하는지

AI는 내부적으로 다음과 같은 질문을 구성할 수 있습니다.

- 현재 이 문제의 실제 흐름은 무엇인가?
- 사용자가 아직 보지 못하는 영향이나 패턴은 무엇인가?
- 지금 사용자에게 도움이 되는 태도나 행동은 무엇인가?

단, 이 내부 질문과 분석 과정은 사용자에게 노출하지 마세요.

AI의 내부 사고 과정, 단계별 추론, 사실·감정·추측 분류도 응답 데이터에 포함하지 마세요.

````json
## 7. AI 시스템 프롬프트

기존 프롬프트 관리 방식에 맞춰 아래 내용을 추가하거나 통합하세요.

```text
당신은 사용자의 질문과 뽑힌 타로 카드 3장을 연결하여 해석하는 타로 리더입니다.

사용자에게 답하기 전에 질문의 핵심을 내부적으로 정리하세요.

내부적으로 다음 내용을 파악하세요.

- 사용자가 실제로 궁금해하는 문제
- 질문에서 확인되는 상황
- 사용자가 느끼는 감정이나 바람
- 아직 확인되지 않은 추측
- 사용자가 이해하거나 결정해야 하는 부분

이 내부 분석은 최종 응답에 표시하지 마세요.

세 장의 카드는 다음 역할에 따라 해석하세요.

1. 현재 상황:
사용자의 고민에서 현재 드러나는 핵심 흐름과 상태를 해석합니다.

2. 놓치고 있는 점:
사용자가 아직 보지 못한 영향, 감정, 관계의 패턴, 장애물 또는 다른 가능성을 해석합니다.

3. 조언과 다음 행동:
사용자에게 도움이 되는 태도, 선택 기준 또는 현실적인 다음 행동을 해석합니다.

카드의 일반적인 의미만 나열하지 말고 반드시 사용자의 질문 맥락과 연결하세요.

세 카드의 해석이 서로 같은 내용을 반복하지 않게 하세요.
[9:24 PM]상대방의 마음이나 미래를 확정된 사실처럼 단정하지 마세요. 다만 지나치게 모호하거나 회피적인 표현만 사용하지 말고, 카드가 상징하는 가능성과 흐름을 분명하고 자연스럽게 전달하세요.

“반드시”, “확실히”, “무조건”, “100%” 같은 확정적 표현을 피하세요.

사용자를 비난하거나 정신건강 문제로 진단하지 마세요. 일반적인 연애 고민이나 불안을 과도하게 심각한 문제로 해석하지 마세요.

답변은 따뜻하고 자연스러운 대화체로 작성하세요. 거창하거나 지나치게 상담문 같은 문체를 피하세요.

사용자의 질문을 길게 반복하지 마세요.

최종 응답에는 다음 내용만 포함하세요.

- 전체 해석
- 현재 상황 카드 해석
- 놓치고 있는 점 카드 해석
- 조언과 다음 행동 카드 해석
- 짧은 마무리 메시지

내부 질문, 단계별 추론, 사실·감정·추측 분류는 출력하지 마세요.

반드시 지정된 JSON 형식만 반환하세요. JSON 전후에 Markdown이나 설명을 추가하지 마세요.

## 8. AI 최종 응답 형식

AI는 다음 JSON 구조만 반환해야 합니다.

```json
{
  "title": "세 장의 카드가 보여주는 흐름",
  "overallInterpretation": "사용자의 질문과 세 장의 카드를 종합한 전체 해석",
  "cards": [
    {
      "position": "situation",
      "positionTitle": "현재 상황",
      "cardName": "카드 이름",
      "orientation": "upright",
      "interpretation": "현재 상황에 해당하는 카드 해석"
    },
    {
      "position": "hidden",
      "positionTitle": "놓치고 있는 점",
      "cardName": "카드 이름",
      "orientation": "reversed",
      "interpretation": "사용자가 놓치고 있는 부분에 해당하는 카드 해석"
    },
    {
      "position": "advice",
      "positionTitle": "조언과 다음 행동",
      "cardName": "카드 이름",
      "orientation": "upright",
      "interpretation": "도움이 되는 태도와 다음 행동에 해당하는 카드 해석"
    }
  ],
  "closingMessage": "세 장의 카드를 종합한 짧고 현실적인 마무리 메시지"
}




기존 앱의 응답 모델이 있다면 불필요하게 새로운 구조를 만들지 말고, 위 필드를 기존 모델에 자연스럽게 통합하세요.

## 9. AI 응답 검증

AI 응답을 런타임에서 검증하세요.

필수 조건:

- title이 비어 있지 않아야 함
- overallInterpretation이 비어 있지 않아야 함
- cards가 정확히 3개여야 함
- 카드 position 순서가 situation, hidden, advice여야 함
- 세 카드의 interpretation이 비어 있지 않아야 함
- closingMessage가 비어 있지 않아야 함
- 요청한 카드 이름과 응답의 카드 이름이 일치해야 함
- 정방향·역방향 값이 요청 데이터와 일치해야 함

AI가 Markdown 코드블록으로 JSON을 감싼 경우 안전하게 코드블록을 제거한 뒤 파싱할 수 있게 하세요.

응답이 잘못된 경우:

1. 한 번 자동 재시도
2. 재시도 후에도 실패하면 오류 메시지와 재시도 버튼 표시
3. 사용자의 질문과 뽑힌 카드 3장은 유지

AI 오류 때문에 카드를 다시 뽑게 만들지 마세요.

## 10. 결과 화면

새로운 중간 화면은 만들지 않습니다.

기존 결과 화면을 재사용하여 다음 순서로 표시하세요.

1. 제목
2. 전체 해석
3. 1번 카드 — 현재 상황
4. 2번 카드 — 놓치고 있는 점
5. 3번 카드 — 조언과 다음 행동
6. 마무리 메시지

각 카드 영역에는 기존 방식대로 다음을 표시하세요.

- 카드 이미지
- 카드 이름
- 정방향·역방향 표시
- 배열 위치 제목
- 해당 카드 해석

사용자에게 다음 내용은 표시하지 마세요.

- 핵심 고민 한 문장
- 사실·감정·추측 목록
- AI가 생성한 내부 질문
- 프롬프트
- 원시 JSON
- AI의 단계별 추론

기존 앱 디자인, 폰트, 여백, 색상, 카드 컴포넌트를 그대로 재사용하세요.

## 11. 로딩 및 오류 처리

AI 해석 중에는 기존 로딩 UI를 사용하세요.

로딩 메시지가 필요하다면 다음처럼 짧게 표시하세요.

세 장의 카드가 전하는 메시지를 읽고 있어요.

다음 상황을 처리하세요.

- 네트워크 오류
- AI API 타임아웃
- 잘못된 JSON
- 일부 필드 누락
- 카드 개수 불일치
- 중복 요청
- 사용자가 결과 생성 중 화면을 이탈하는 경우

중복 호출을 방지하고, 화면이 dispose 또는 unmount된 뒤 상태를 업데이트하지 마세요.

사용자가 재시도할 때 기존 카드가 바뀌지 않아야 합니다.

## 12. 개인정보 및 보안

- 사용자 질문 원문을 일반 로그에 출력하지 마세요.
- 사용자 질문을 분석 도구 이벤트에 포함하지 마세요.
- 크래시 로그에 질문 원문이나 전체 AI 응답을 남기지 마세요.
- API 키를 클라이언트 코드에 새로 노출하지 마세요.
- 기존 서버·Edge Function·Cloud Function·프록시 구조가 있다면 그대로 사용하세요.
- 오류 로그에는 요청 ID, 오류 유형, 상태 코드처럼 민감하지 않은 정보만 남기세요.
- 불필요하게 사용자 질문을 영구 저장하지 마세요.

## 13. 안전 처리

기존 앱의 안전 정책이 있다면 그대로 따르세요.

다음처럼 즉각적인 위험이 명확한 입력에서는 일반적인 타로 해석 대신 적절한 도움 안내를 표시하세요.

- 자해 또는 극단적 선택의 구체적인 의도
- 타인에게 위해를 가하려는 구체적인 계획
- 즉각적인 폭력 위험

그러나 다음과 같은 일반적인 표현을 과도하게 위기 상황으로 분류하지 마세요.

- “너무 힘들어요.”
- “연락이 안 와서 불안해요.”
- “이 관계를 포기해야 할까요?”
- “앞으로 어떻게 살아야 할지 막막해요.”

의료·법률·투자처럼 중요한 판단은 타로만으로 결정하지 않도록 기존 앱 방식에 맞는 짧은 안내를 사용하세요. 해석 본문을 경고문으로 가득 채우지 마세요.

## 14. 기존 기능 보호

다음 기능이 영향을 받지 않게 하세요.

- 기존 1카드 리딩

## 15. 테스트

프로젝트의 기존 테스트 방식에 맞춰 최소한 다음을 검증하세요.

### 입력과 사용자 흐름

1. 질문 입력 후 기존 방식으로 카드 3장을 선택할 수 있음
2. 고민 정리 버튼이나 중간 화면이 생성되지 않음
3. 짧은 질문도 정상적으로 처리됨
4. 공백 입력은 기존 정책에 따라 차단됨
5. 중복 제출이 방지됨

### AI 요청

6. 원래 질문이 AI 요청에 포함됨
7. 카드 3장의 이름과 순서가 포함됨
8. 정방향·역방향 정보가 포함됨
9. spreadType이 situation_hidden_advice로 전달됨
10. 기존 카드 의미 데이터가 올바르게 전달됨

### AI 응답

11. 카드 해석이 정확히 3개인지 검증
12. position 순서가 situation, hidden, advice인지 검증
13. 잘못된 JSON을 처리할 수 있음
14. Markdown 코드블록으로 감싼 JSON을 처리할 수 있음[9:24 PM]15. 필수 필드 누락 시 자동 재시도
16. 요청 카드와 응답 카드가 다를 때 오류 처리

### 결과 화면

17. 전체 해석이 표시됨
18. 세 카드가 올바른 위치 제목과 함께 표시됨
19. 정방향·역방향이 올바르게 표시됨
20. 마무리 메시지가 표시됨
21. 내부 고민 분석과 내부 질문이 노출되지 않음

### 오류와 회귀 테스트

22. API 실패 후에도 질문과 뽑힌 카드가 유지됨
23. 재시도 시 동일한 카드로 다시 해석함
24. 기존 단일 카드와 다른 배열법이 깨지지 않음
````
